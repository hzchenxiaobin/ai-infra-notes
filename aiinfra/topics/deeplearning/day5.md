### 全连接网络看图，问题在哪？

昨天我们用 `nn.Flatten()` 把 28×28 的图片**拉平成 784 个数字**再送进网络。这有两个问题：

**问题 1：破坏了空间结构**

```
一张图：              拉平后：
┌─────┐
│  ██ │    →    [0,0,1,1,0, ..., 1,1,0,0]  谁挨着谁？不知道了
│ ██  │
└─────┘
```

像素之间的相邻关系（这是"竖"、这是"横"、这是"拐角"）全部丢失。把图片像素随机打乱再拉平，全连接网络照学不误——它根本没用上"这是一张图"这个事实。

**问题 2：参数量爆炸**

一张 224×224 的彩色照片拉平是 15 万个输入，接一个 1000 神经元的全连接层就是 1.5 亿个参数——大部分参数都在做重复劳动。

### 卷积：带着"小模板"在图上滑动探测

**卷积核（kernel/filter）= 特征探测器**。比如一个 3×3 的卷积核，就是一张小模板，在整张图上从左到右、从上往下滑动，每到一个位置就问一句："这一片区域长得像我的模板吗？"像就打高分，不像就打低分。

```
一个"竖线探测器"卷积核滑过图片后：
原图有竖线的地方 → 输出高分（亮点）
没有竖线的地方   → 输出低分（暗点）
→ 得到一张"竖线分布图"（特征图，feature map）
```

关键设计，也是 CNN 省参数的原因：

- **参数共享**：同一个探测器扫全图，不管特征出现在左上角还是右下角，用同一套参数就能发现。全连接网络则要为每个位置单独学一套参数
- **局部连接**：每个输出只看输入的一小片区域（感受野），符合"局部像素组合成图案"的直觉
- **层层抽象**：第一层学边缘/拐角 → 第二层学纹理/形状 → 更深层学"眼睛""轮子"这类部件——越深的层，特征越抽象

### 池化（Pooling）：压缩特征图

最常用的是**最大池化（MaxPooling）**：把 2×2 的区域压缩成 1 个值，取最大值。

```
作用：
1. 特征图尺寸减半 → 计算量下降
2. 保留"这里有没有这个特征"，丢掉"精确在哪" → 对微小位移更鲁棒
   （数字 7 写得偏左一点偏右一点，都还是 7）
```

### 一个典型 CNN 的全貌

```
输入图片 → [卷积 → ReLU → 池化] × 若干次 → 拉平 → 全连接层 → 分类输出
            └─ 提取特征（CNN 的活）─┘        └─ 做决策（老熟人）─┘
```

### 自测三问

1. 为什么全连接网络处理大图片会参数爆炸，CNN 却不会？
2. "参数共享"是什么意思？它给 CNN 带来了什么好处？
3. 池化丢掉了位置信息，为什么反而是件好事？

### 参考实现（只有"定义网络"部分变了）

```python
model = nn.Sequential(
    # —— 特征提取：卷积部分 ——
    # 输入: [batch, 1, 28, 28]（灰度图 = 1 个通道）
    nn.Conv2d(in_channels=1, out_channels=32, kernel_size=3, padding=1),
    # → [batch, 32, 28, 28]  32 个探测器，每个产一张 28×28 特征图
    nn.ReLU(),
    nn.MaxPool2d(kernel_size=2),
    # → [batch, 32, 14, 14]  尺寸减半

    nn.Conv2d(32, 64, kernel_size=3, padding=1),
    # → [batch, 64, 14, 14]
    nn.ReLU(),
    nn.MaxPool2d(2),
    # → [batch, 64, 7, 7]

    # —— 决策部分：拉平 + 全连接 ——
    nn.Flatten(),                    # 64×7×7 = 3136
    nn.Linear(64 * 7 * 7, 128),
    nn.ReLU(),
    nn.Dropout(0.5),
    nn.Linear(128, 10),
)
```

**逐层看懂维度变化**是今天的核心功课。手工推一遍上面注释里的每个 `[batch, C, H, W]`，推不出来的地方就是没理解的地方：

- `Conv2d` 的输出尺寸：`H_out = H - kernel_size + 2×padding + 1`（stride=1 时）。本题 `28 - 3 + 2×1 + 1 = 28`，尺寸不变
- `MaxPool2d(2)`：高宽各减半
- 通道数 = 卷积核个数 = `out_channels`

## 常见坑提醒

1. **`Flatten` 后的数字算错**——`Linear` 的 `in_features` 必须等于 `通道数×高×宽`，报错 `mat1 and mat2 shapes` 就是这里不匹配，回去推维度
2. **忘记图片有"通道"维**——全连接网络输入是 `[batch, 784]`，CNN 输入是 `[batch, 1, 28, 28]`，MNIST 数据天然带通道维，直接用即可，别再 `Flatten()`
3. **padding 的作用**：`kernel_size=3, padding=1` 保持尺寸不变，方便心算维度；不加 padding 每卷一次小一圈
4. **CIFAR-10 准确率上不去别慌**——简单 CNN 上限就在那，Day 7 的迁移学习会见识真正的图像模型

---

**自测答案**：`Conv2d(3→16, k=5)`：`32 - 5 + 1 = 28`，输出 `[1, 16, 28, 28]`；再 `MaxPool2d(2)`：`[1, 16, 14, 14]`。
