### 学习任务 1：Decoder-only Transformer 与推理经济学回顾（40 分钟）

#### 推理的两个阶段：Prefill 与 Decode

现代开源大模型（DeepSeek、Kimi、Llama、Qwen）全部是 **Decoder-only Transformer**。推理时一个请求分两个阶段：

| 阶段 | 做什么 | 计算特征 | 瓶颈 |
|------|--------|---------|------|
| **Prefill**（预填充） | 一次性处理全部输入 prompt | 矩阵-矩阵乘，并行度高 | 算力（compute-bound） |
| **Decode**（逐词生成） | 每步只生成 1 个 token | 矩阵-向量乘，并行度低 | 显存带宽（memory-bound） |

Decode 阶段每生成一个 token，都要和**之前所有 token** 做注意力。如果每步都重算历史 token 的 $K, V$，第 $t$ 步的计算量是 $O(t \cdot d^2)$，整段生成是 $O(n^2 d^2)$——完全无法接受。

#### KV cache：用显存换时间

解决方案是**缓存**历史 token 的 $K, V$ 向量，每步只需为新 token 算一次 $K, V$ 并追加进缓存：

$$\text{KV cache 大小} = 2 \times L \times n_h \times d_h \times n \times \text{bytes}$$

- $2$：$K$ 和 $V$ 各一份
- $L$：层数，$n_h$：注意力头数，$d_h$：每头维度
- $n$：序列长度（prompt + 已生成 token）
- $\text{bytes}$：每元素字节数（BF16 = 2）

> 💡 **一句话总结**：KV cache 是推理显存的"第二大头"（第一是权重）。长上下文 + 大 batch 时它会超过权重本身——**谁压得住 KV cache，谁就能便宜地卖长上下文**。这就是 Day 1 下半场的 MLA 和 Day 4 的 DSA 存在的理由。

#### 为什么这对"读论文"重要

技术报告的架构章节里每个设计选择，最终都要落到这三笔账上：

| 账 | 问题 | V3 的答案（预告） |
|----|------|------------------|
| 权重显存 | 模型装得下吗？ | MoE：总参数 671B 但推理可分布式部署 |
| KV cache 显存 | 长上下文 + 高并发装得下吗？ | MLA：每 token 缓存压到 576 维 |
| 每 token FLOPs | 生成快不快、贵不贵？ | MoE：每 token 只激活 37B |

### 学习任务 2：注意力变体族谱 —— MHA → MQA → GQA（40 分钟）

在 MLA 之前，工业界压缩 KV cache 的路线是"减少 KV 头的数量"。理解这条演进线，才能体会 MLA 换了一条什么赛道。

#### MHA（Multi-Head Attention，标准版）

每个注意力头都有自己独立的 $K, V$ 投影：

$$K = XW^K \in \mathbb{R}^{n \times (n_h d_h)}, \quad V = XW^V \in \mathbb{R}^{n \times (n_h d_h)}$$

- 每 token 每层缓存：$2 \times n_h \times d_h$ 个元素
- 表达力最强，但 KV cache 最大

#### MQA（Multi-Query Attention，2019）

所有 $n_h$ 个查询头**共享同一份** $K, V$（即只有 1 个 KV 头）：

- 每 token 每层缓存：$2 \times d_h$（缩小 $n_h$ 倍）
- 代价：质量明显下降——所有头被迫"看同一个视角"

#### GQA（Grouped-Query Attention，2023）

折中：把 $n_h$ 个头分成 $G$ 组，组内共享 $K, V$：

- 每 token 每层缓存：$2 \times G \times d_h$
- Llama 2/3 70B 用 $G = 8$（64 个 Q 头，8 个 KV 头），质量接近 MHA

#### 三种方案对比（以 DeepSeek-V3 的注意力配置为基准：$n_h = 128$，$d_h = 128$）

| 方案 | KV 头数 | 每 token 每层缓存（元素） | 相对 MHA | 质量 |
|------|---------|--------------------------|----------|------|
| MHA | 128 | $2 \times 128 \times 128 = 32768$ | 1× | 最好 |
| GQA（G=8） | 8 | $2 \times 8 \times 128 = 2048$ | 1/16 | 接近 MHA |
| MQA | 1 | $2 \times 128 = 256$ | 1/128 | 明显掉点 |
| **MLA（V3）** | —（压缩表示） | $512 + 64 = 576$ | **1/57** | **不降反升**（见任务 3） |

> 💡 **关键观察**：MQA/GQA 是"做减法"——砍掉 KV 头，缓存小了但信息容量也小了。MLA 换了个思路：**不砍头，而是把所有头的 KV 联合压缩到一个低秩潜向量里**，缓存的是压缩表示，用时再"解压"。信息论上这比砍头优雅得多。

> ⚠️ **注意**：GQA 至今仍是工业界主流（Llama、Qwen 都在用），因为它实现简单、不改动注意力计算本身。MLA 的推理优化（矩阵吸收、权重重排）工程复杂度高得多——这也是"读论文"和"落地"之间的差距，Day 3 讲基础设施时会再遇到。

### 学习任务 3：MLA 精读 —— 把 KV 压进"潜向量"（60 分钟，今日核心）

精读 V3 报告 §2.1.1。MLA（Multi-head Latent Attention，多头潜在注意力）首次出现于 DeepSeek-V2（可对照 [DeepSeek-V2 论文精读](../../paper/deepseek_v2/README.md)），V3 沿用。

#### 核心思想：低秩联合压缩

MHA 为每个头存 $d_h$ 维的 $K$ 和 $V$，本质是存了 $2 n_h d_h = 32768$ 维的向量。MLA 的观察：这 32768 维信息是**低秩**的，可以压缩到一个 $d_c = 512$ 维的潜向量里：

$$c_t^{KV} = W^{DKV} h_t \in \mathbb{R}^{512}$$

$$k_t^C = W^{UK} c_t^{KV}, \quad v_t^C = W^{UV} c_t^{KV}$$

- $W^{DKV}$：下投影（$7168 \to 512$），推理时**只缓存 $c_t^{KV}$**
- $W^{UK}, W^{UV}$：上投影（$512 \to$ 各头的 $K, V$），用时解压

类比：MQA 是"只存一张照片，所有人共用"；MLA 是"存一份压缩文件，每个人解压出自己的版本"。

#### 麻烦来了：RoPE 与压缩不兼容

现代模型用 RoPE（旋转位置编码），它作用在 $q, k$ 上且**依赖位置**——位置 $t$ 的旋转矩阵不同。如果先压缩再上投影，RoPE 会"卡在"两个矩阵中间，导致推理时无法把上投影矩阵预先合并掉（矩阵吸收失效，见下文）。

MLA 的解法：**解耦 RoPE（Decoupled RoPE）**——把位置信息从压缩通路里拆出来，单独走一条小路：

$$k_t = [k_t^C; \ k_t^R], \quad k_t^R = \text{RoPE}(W^{KR} h_t) \in \mathbb{R}^{64}$$

- $k^C$（128 维/头）：走压缩通路，负责内容匹配
- $k^R$（64 维，所有头共享）：不走压缩，专门携带位置信息
- 查询侧同样处理：$q_t = [q_t^C; \ q_t^R]$，且 $q$ 也做了压缩（$c_t^Q = W^{DQ} h_t \in \mathbb{R}^{1536}$，训练时省激活显存）

最终注意力分数：

$$\text{score}_{t,j} = \frac{(q_t^C)^T k_j^C + (q_t^R)^T k_j^R}{\sqrt{d_h + d_h^R}}$$

#### 推理时的关键技巧：矩阵吸收（Matrix Absorption）

朴素实现的 MLA 推理反而更慢——每步都要把 $c^{KV}$ 解压成完整的 $K, V$。工程上的做法是**不缓存解压后的 $K, V$，直接在潜向量上做注意力**：

$$(q_t^C)^T k_j^C = (W^{UQ} c_t^Q)^T (W^{UK} c_j^{KV}) = (c_t^Q)^T \underbrace{(W^{UQ})^T W^{UK}}_{\text{可预先合并为一个矩阵}} c_j^{KV}$$

- $W^{UK}$ 被"吸收"进查询侧，$W^{UV}$ 被吸收进输出投影 $W^O$
- 推理时只需缓存 $c_t^{KV}$（512 维）+ $k_t^R$（64 维）= **每 token 每层 576 个元素**
- 这就是为什么 MLA 的 KV cache 和 GQA($G{\approx}2$) 相当，却保留了 128 个头的表达力

#### MLA 显存账（V3 配置，61 层，BF16）

| 方案 | 每 token 每层 | 每 token 全模型 | 128K 上下文 × batch 1 |
|------|--------------|----------------|----------------------|
| MHA | $2 \times 128 \times 128 = 32768$ 元素 | 32768 × 61 × 2B ≈ **4.0 MB** | ≈ **523 GB**（不可行） |
| MLA | $512 + 64 = 576$ 元素 | 576 × 61 × 2B ≈ **70 KB** | ≈ **9.2 GB**（轻松） |

压缩比 $32768 / 576 \approx 57\times$。这就是"MLA 省显存"的精确含义。

> 💡 **一句话总结**：MLA = 低秩压缩（$c^{KV}$ 潜向量）+ 解耦 RoPE（位置信息单独走）+ 矩阵吸收（推理直接在潜空间做注意力）。三件事缺一不可：没有解耦 RoPE 就没法吸收，没有吸收就只是"省缓存不省计算"。

> ⚠️ **常见误解**：MLA 不只是"省显存"，V2 论文的消融显示它性能**优于**同配置 MHA——低秩瓶颈起到了正则化作用。所以 MLA 是"又便宜又好"，这是它能从 V2 一路沿用到 V3、V3.2 的原因。

### 学习任务 4：DeepSeekMoE 精读 —— 稀疏激活的极致（60 分钟，今日核心）

精读 V3 报告 §2.1.2。V3 共 61 层：**前 3 层是稠密 FFN，后 58 层全部换成 MoE**。

#### 基本结构：1 共享 + 256 路由，Top-8

每个 MoE 层的输出：

$$h_t' = u_t + \sum_{i=1}^{N_s} \text{FFN}_i^{(s)}(u_t) + \sum_{i=1}^{N_r} g_{i,t} \cdot \text{FFN}_i^{(r)}(u_t)$$

- $N_s = 1$ 个**共享专家**：所有 token 必过，捕捉通用知识
- $N_r = 256$ 个**路由专家**：每个专家 FFN 中间维度 2048（细粒度小专家）
- 每个 token 激活其中 $K_r = 8$ 个

为什么细粒度？组合空间 $\binom{256}{8} \approx 4.4 \times 10^{14}$，对比 Mixtral 的 $\binom{8}{2} = 28$——专家可以极致专精（详见 [MoE 专题](../moe/README.md) Day 1 的演进表）。

#### 创新点 1：Sigmoid 门控 + 无辅助损失负载均衡

传统 MoE 用 softmax 门控 + auxiliary loss 防路由崩塌（负载不均），但辅助损失和主任务目标冲突，调不好会掉点。V3 的方案：

$$s_{i,t} = \text{Sigmoid}(u_t^T e_i)$$

- **路由决策**用加了偏置的分数：选 Top-8 时按 $s_{i,t} + b_i$ 排序
- **门控权重**仍用原始分数归一化：$g_{i,t} = s_{i,t} / \sum_{j \in \text{Top-8}} s_{j,t}$

偏置 $b_i$ 的动态调整规则简单粗暴：

- 某专家负载过高 → $b_i \leftarrow b_i - \gamma$（$\gamma = 0.001$）
- 某专家负载过低 → $b_i \leftarrow b_i + \gamma$

> 💡 **关键洞察**：$b_i$ 只影响"选谁"，不影响"选中后的权重"——负载均衡被移出了梯度优化的目标函数，变成一个独立的控制回路。这就是 "auxiliary-loss-free" 的含义：不用辅助损失打扰主任务，靠一个动态偏置把负载"拧"均匀。V3 还保留了一个极小的序列级辅助损失（单序列内防极端不均）作为兜底。

#### 创新点 2：节点受限路由（Node-Limited Routing）

256 个专家分布在 8 个节点（64 张 GPU）上做专家并行。若 Top-8 专家散落在 8 个节点，每 token 要通信 8 次。V3 限制**每个 token 最多发往 $M = 4$ 个节点**：

- 先按专家亲和力之和对节点排序，选出前 4 个节点
- 再在这 4 个节点的专家里做 Top-8
- 通信开销直接砍半，性能几乎无损

#### 创新点 3：训练全程不丢 token（No Token-Dropping）

传统 MoE 用容量因子限制每专家 token 数、超限丢弃（训练省算力）。V3 靠无辅助损失均衡 + 节点受限路由把负载控制得足够好，**训练全程不丢任何 token**——训练-推理行为完全一致。

#### 顺带一提：MTP（Multi-Token Prediction）

V3 架构章节的第三个组件：训练时不仅预测下一个 token，还用 1 个额外的 MTP 模块预测"下下个 token"（深度 $D=1$）。两个作用：

- 训练：提供更稠密的监督信号，提升数据效率
- 推理：MTP 模块可用于投机解码（self-speculative decoding）加速生成

Day 3 讲训练效率、以及后面读 V3.2/K2 时会再遇到它，今天知道"它是什么、挂在哪"即可。

### 学习任务 5：动手笔算 —— 671B / 37B 拆解与 KV cache 账单（60 分钟）

这是 README 布置的动手任务。**合上论文，只用下面这组超参数，自己推一遍**（可以最后对照）：

| 超参数 | 值 | 超参数 | 值 |
|--------|-----|--------|-----|
| 层数 $L$ | 61（3 稠密 + 58 MoE） | 隐藏维度 $d$ | 7168 |
| 注意力头数 $n_h$ | 128 | 每头维度 $d_h$ | 128 |
| KV 压缩维度 $d_c$ | 512 | Q 压缩维度 $d_c'$ | 1536 |
| 解耦 RoPE 维度 $d_h^R$ | 64 | 路由专家数 $N_r$ | 256（Top-8） |
| 共享专家数 $N_s$ | 1 | 专家 FFN 中间维度 | 2048 |
| 稠密层 FFN 中间维度 | 18432 | 词表大小 | 约 129K |

#### 第一步：单个专家的参数量

SwiGLU 风格 FFN 有 3 个矩阵（$W_1, W_2, W_3$）：

$$3 \times d \times d_{ff} = 3 \times 7168 \times 2048 \approx 44.0\ \text{M}$$

#### 第二步：MoE 层的专家参数

- 总专家参数/层：$(256 + 1) \times 44.0\ \text{M} \approx 11.3\ \text{B}$
- **每 token 激活**的专家参数/层：$(8 + 1) \times 44.0\ \text{M} \approx 396\ \text{M}$

#### 第三步：注意力参数（MLA，每层，所有 token 都算）

| 矩阵 | 形状 | 参数量 |
|------|------|--------|
| $W^{DQ}$ | $7168 \times 1536$ | 11.0 M |
| $W^{UQ} + W^{QR}$ | $1536 \times 128 \times (128{+}64)$ | 37.7 M |
| $W^{DKV}$ | $7168 \times (512{+}64)$ | 4.1 M |
| $W^{UK} + W^{UV}$ | $2 \times 512 \times 128 \times 128$ | 16.8 M |
| $W^{KR}$ | $7168 \times 64$ | 0.5 M |
| $W^O$ | $(128 \times 128) \times 7168$ | 117.4 M |
| **合计** | | **≈ 176 M** |

#### 第四步：汇总（单位：B）

| 部分 | 总参数 | 每 token 激活 |
|------|--------|--------------|
| 58 个 MoE 层专家 | $58 \times 11.3 \approx 655$ | $58 \times 0.396 \approx 23.0$ |
| 61 层注意力 | $61 \times 0.176 \approx 10.7$ | 10.7（稠密，全算） |
| 3 个稠密层 FFN | $3 \times 3 \times 7168 \times 18432 \approx 1.2$ | 1.2 |
| Embedding + 输出头 | $2 \times 129K \times 7168 \approx 1.9$ | ≈ 0.9（查表不算 FLOPs） |
| **合计** | **≈ 671 B** ✓ | **≈ 37 B** ✓ |

两个数字都对上了——这就是"671B 总参数、37B 激活"的精确构成。

#### 第五步：回答"MoE 为什么参数多但算得便宜"

每 token 前向 FLOPs ≈ $2 \times$ 激活参数量 ≈ $2 \times 37\text{B} = 74\ \text{GFLOPs}$。如果是同等能力的稠密 671B 模型，则是 $2 \times 671\text{B} = 1.34\ \text{TFLOPs}$——**差了 18 倍**。MoE 的本质：

- **容量**（能记住多少知识）∝ 总参数 671B
- **成本**（每 token 算多少）∝ 激活参数 37B
- 两者解耦 = "用 37B 的价钱，买 671B 的脑子"

代价是显存：671B 参数（BF16 ≈ 1.3 TB）必须全部驻留，所以 MoE 推理/训练必须多卡专家并行——这笔账 Day 3 接着算。

#### 第六步（可选）：算 KV cache

用任务 3 的公式验证：128K 上下文、batch=32 时，MLA 的 KV cache ≈ $70\ \text{KB} \times 128K \times 32 \approx 287\ \text{GB}$；若用 MHA 则是 $4.0\ \text{MB} \times 128K \times 32 \approx 16\ \text{TB}$。这个对比就是"V4 敢默认 1M 上下文"的底气来源（Day 4 的 DSA 再砍一刀）。

### 面试题积累（今日 3 道）

**Q1：MLA 为什么能大幅压缩 KV cache？它和 GQA 的本质区别是什么？**
> MLA 把所有头的 $K, V$ 联合低秩压缩到一个 $d_c = 512$ 维的潜向量 $c^{KV} = W^{DKV} h$，推理时只缓存潜向量 + 64 维解耦 RoPE key，共 576 维/token/层，对比 MHA 的 $2 n_h d_h = 32768$ 维压缩约 57 倍。与 GQA 的本质区别：GQA 是"做减法"——让多个 Q 头共享同一份 KV，缓存小了但信息容量同步损失；MLA 是"压缩"——128 个头各自从潜向量解压出自己的 KV，表达力不降反升。工程上 MLA 还依赖两个配套设计：解耦 RoPE（位置信息单独走 64 维小路，否则 RoPE 的位置依赖性会让压缩失效）和矩阵吸收（推理时把 $W^{UK}$ 吸收进查询侧、$W^{UV}$ 吸收进 $W^O$，直接在潜空间做注意力，省缓存也省计算）。

**Q2：MoE 为什么能"参数多但算得便宜"？推理时每 token 实际用多少参数？**
> MoE 把稠密 FFN 换成 $N$ 个小专家 + Top-K 路由，每 token 只激活 $K \ll N$ 个专家，把"模型容量"（∝ 总参数）和"每 token 计算量"（∝ 激活参数）解耦。以 DeepSeek-V3 为例：256 路由专家选 8 + 1 共享专家，每 token 激活约 37B（专家 23B + 注意力 10.7B + 稠密层与 embedding 约 3B），前向 FLOPs ≈ 74 GFLOPs；等容量稠密模型要 1.34 TFLOPs，差 18 倍。代价是"省算力不省显存"——671B 权重必须全部驻留显存，需要专家并行把专家铺到多卡，并引入 all-to-all 通信，V3 用节点受限路由（每 token 最多发 4 个节点）压制通信。

**Q3：DeepSeek-V3 的负载均衡为什么敢去掉辅助损失？具体怎么做的？**
> 传统 MoE 靠 auxiliary loss 惩罚负载不均，但它与主任务目标冲突，权重调大掉点、调小没效果。V3 把负载均衡移出梯度优化：给每个专家一个偏置 $b_i$，Top-8 路由决策按 $s_{i,t} + b_i$ 排序，但选中后的门控权重仍用原始 sigmoid 分数 $s_{i,t}$ 归一化——偏置只影响"选谁"，不污染"算多少"。训练中监控每步负载，过载专家 $b_i \mathrel{-}= \gamma$、欠载专家 $b_i \mathrel{+}= \gamma$（$\gamma = 0.001$），相当于一个独立的反馈控制回路。另配一个极小的序列级辅助损失兜底（防单序列内极端不均）。效果是训练全程零 token 丢弃，负载均衡且不伤主任务性能。
