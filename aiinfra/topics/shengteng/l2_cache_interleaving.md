# 昇腾950 L2 Cache 微架构：512B 低位交织与高位异或交织

> 图示说明：[l2_cache_interleaving.svg](l2_cache_interleaving.svg)
>
> 对应白皮书第 4.3.2 节《L2 Cache 特性》原文：
> “多 Bank 分布式架构，512B 低位交织（采用高位异或交织，交织算法升级）；Cache Line 粒度 512B，新增支持 128B Sector Cache 特性，128B/256B 访问更高效；每个 Bank 支持同时读写。”

---

## 1. 什么是“交织（Interleaving）”

交织是一种把数据按固定粒度**分散存储到多个 Bank** 上的地址映射技术。当连续地址的数据被分布到不同 Bank 时，多个 Bank 可以**并行服务**连续的访问请求，从而把有效带宽从“单 Bank 带宽”提升到“单 Bank 带宽 × Bank 数”。

- **交织粒度（Interleave Granularity）**：作为最小分配单元的数据块大小，这里是 **512B**。
- **Bank 索引（Bank Index）**：给定一个物理地址，决定它落在哪个 Bank 的计算规则。

---

## 2. “512B 低位交织”具体含义

### 2.1 两个关键词

| 关键词 | 含义 |
|---|---|
| **512B** | 交织粒度 = 512 字节 = **一个 Cache Line 大小**。即每 512B 的数据块作为一个交织单元。 |
| **低位交织** | 用地址的**低位段**来决定数据落在哪个 Bank（而非用高位段）。 |

### 2.2 工作原理（示意）

假设有 4 个 Bank、交织粒度 512B。纯低位交织时，Bank 索引取地址的第 9~10 位（因为 512 = 2⁹，4 = 2²）：

```
地址范围            Bank
0x0000 ~ 0x01FF  →  Bank 0   (bit[10:9] = 00)
0x0200 ~ 0x03FF  →  Bank 1   (bit[10:9] = 01)
0x0400 ~ 0x05FF  →  Bank 2   (bit[10:9] = 10)
0x0600 ~ 0x07FF  →  Bank 3   (bit[10:9] = 11)
0x0800 ~ 0x09FF  →  Bank 0   (bit[10:9] = 00)  ← 回到 Bank 0，循环
...
```

可以看到：**相邻的 512B 缓存行天然落在不同 Bank 上**（Bank0→1→2→3→0→…），一次连续的 Cache Line 填充序列会被 4 个 Bank 并行服务，带宽近似线性扩展。

### 2.3 为什么以 512B（= Cache Line）为粒度

- 一次 Cache Line 填充（fill）只访问**一个 Bank**，避免一次填充跨多 Bank 的协议开销；
- 与“每个 Bank 支持同时读写”配合，连续流式访问可被多 Bank 并行吸收；
- 512B Cache Line 再细分为 **4 × 128B Sector**，对 128B/256B 的小包访问只需激活对应 Sector，不必整行读写，提升离散小包场景效率。

---

## 3. “高位异或交织”：低位交织的增强

白皮书原文在“512B 低位交织”后紧跟括号注明“**采用高位异或交织，交织算法升级**”。这是在纯低位交织基础上的**冲突消解增强**。

### 3.1 纯低位交织的缺陷

低位交织对**连续访问**最优，但对**等步长（stride）访问**存在 Bank 冲突风险：

> 若访问步长恰好是 `Bank数 × 512B` 的整数倍，则所有访问的低位段相同，全部命中同一 Bank，带宽退化为单 Bank。

例如步长 = 4×512 = 2048B 时，每次访问 bit[10:9] 都是 00，全部打到 Bank 0。

### 3.2 异或交织如何消解

将地址的**某些高位比特**通过异或（XOR）函数混入 Bank 索引计算：

```
bank_index = 低位交织索引  XOR  f(地址高位)
```

- 不同“步长组”的访问因高位不同，被 XOR 函数**进一步打散**到不同 Bank；
- 对连续访问（高位不变）仍保持低位交织的并行优势；
- 本质是把“地址 → Bank”的映射从**线性循环**变为**伪随机散列**，降低规则性访问模式下的冲突率。

> ⚠️ 白皮书未公开具体异或函数，此处仅说明设计原理，不代表昇腾950 的实际算法。

### 3.3 升级效果

白皮书原文称：“在离散小包访问和随机访存场景下，同带宽条件下性能较上一代提升 **2 倍以上**。” 这与 **低位异或交织 + 128B Sector Cache** 的协同设计直接相关：

- 低位交织 → 连续访问并行；
- 高位异或 → stride/随机访问去冲突；
- 128B Sector → 小包访问不浪费整行带宽。

---

## 4. 与其他 L2 特性的协同

| L2 特性 | 与交织的关系 |
|---|---|
| **多 Bank 分布式** | 交织的前提：必须有多个可独立读写的 Bank 才能并行。 |
| **512B Cache Line / 4×128B Sector** | 交织粒度 = Cache Line；Sector 让小包访问不触达整行，与交织共同提升离散访问效率。 |
| **L2 Hint（allocate / non-allocate）** | 程序员控制数据是否进 L2，与交织配合可避免冷数据驱逐热数据，提升局部性。 |
| **CMO（Prefetch/Writeback/Invalid/Flush）** | 经 SDMA 的 L2 管理操作，与交织无直接耦合，但预取效果依赖多 Bank 并行带宽。 |
| **2 Die UMA + 硬件一致性** | L2 有“局部亲和性”，跨 Die 访问延迟更高；交织在单 Die 内生效，Die 间一致性由硬件维护。 |

---

## 5. 一句话总结

**“512B 低位交织”** = 以 512B（一个 Cache Line）为粒度，用地址低位做 Bank 选择，使连续缓存行分散到不同 Bank 以支持并行访问；**“高位异或交织”** 是其增强算法，把高位通过 XOR 混入 Bank 索引，打散 stride/随机访问的 Bank 冲突，在离散小包与随机访存场景下获得 2 倍以上的同带宽性能提升。
